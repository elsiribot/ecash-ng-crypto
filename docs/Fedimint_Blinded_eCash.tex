\title{Fedimint Confidential eCash\\[4pt]\large Threshold-issued, value-hiding, unlinkable notes from Pointcheval--Sanders signatures}
\author{Gazelle}
\date{July 2026 \\ \small revised September 2026}

\begin{document}
\maketitle

\begin{abstract}
Fedimint issues eCash notes from a federation of mints using blind signatures,
which hides \emph{who} spends a note but not \emph{how much} it is worth: every
note carries a public denomination. We describe a confidential variant in which
the amount is a hidden attribute of a threshold-issued anonymous credential. A
note is a Pointcheval--Sanders signature over three hidden attributes (amount,
serial secret, spend condition), issued blindly by any $t$ of $n$ mints following
the Coconut construction in the Pedersen-commitment form used by Nym; the amount
is additionally carried in a Pedersen commitment so that transactions can be
balanced homomorphically and range-proven with Bulletproofs. Spending shows a
re-randomised signature together with a deterministic nullifier and a short
$\Sigma$-proof, so that spends are unlinkable to issuance and double spends are
detected by nullifier equality. We fix the notation, explain the purpose of
every element of the construction, give the security model and proof sketches,
describe how notes compose into transactions, and analyse an amortised
$\Sigma$-proof that keeps the issuance proof at a constant 496 bytes for any
number of notes. We show that the amortisation as implemented shares one
signature base across a batch and thereby enables an affine-combination forgery
of PS signatures; we give a partially amortised variant with per-note bases
that avoids it at about 192 bytes per note. We report proof and transaction
sizes and timings of a Rust prototype over BLS12-381.
\end{abstract}

\section{Introduction}

Electronic cash (eCash) aims to provide a digital analogue of physical cash,
enabling users to perform electronic payments while preserving strong privacy
guarantees. Traditional eCash systems focus on anonymity by preventing the
issuer from linking the withdrawal of a coin to its subsequent spending through
the use of blind signatures. More recent constructions extend this notion of
privacy by providing \emph{confidential} eCash, where not only the identity of
the user remains protected, but also the value of the eCash note. In such
systems, the denomination is cryptographically hidden from all parties except
those authorized to learn it, while still allowing the correctness of
transactions to be publicly verified.

Designing a confidential blind eCash system requires satisfying several
fundamental security and practical properties. First, the system should
guarantee \textbf{unlinkability}, ensuring that an issued note cannot be linked
to the transaction in which it is later spent, thereby preserving the user's
anonymity. Second, it must satisfy \textbf{unforgeability}, meaning that every
valid eCash note must originate from the mint and that no adversary can create
additional spendable notes or increase their value. Third, the protocol should
support \textbf{offline transactions}, allowing payments to be completed
without requiring communication with the mint during the spending phase.
Finally, the construction should be \textbf{practical}, with cryptographic
proofs and transaction sizes that remain compact and computational costs that
are sufficiently low for deployment in real-world payment systems.

Fedimint today meets the first three goals with blind BLS signatures over a
fixed set of denominations~\cite{fedimint}: a note is a signature on a random
serial, and its value is the public denomination of the key that signed it.
Hiding the value therefore needs a different primitive: a signature on a
\emph{hidden} amount that can still be verified, balanced against other notes,
and bounded to a legal range. Anonymous credentials provide exactly this, and
the Coconut construction~\cite{coconut} makes them threshold-issuable, which
matches a federation of mints.

\paragraph{Contributions.} This paper describes such a confidential federated
eCash scheme and the prototype that implements it. Concretely, it
\begin{itemize}[nosep]
  \item presents the construction with a complete, typed notation
        (Section~\ref{sec:notation}) and explains, for every element of the
        issuance request, the signature and the spend, which security property
        it exists for (Section~\ref{sec:scheme});
  \item states the system model, the threat model and the security goals
        (Section~\ref{sec:model}) and gives proof sketches reducing each goal to
        standard assumptions (Section~\ref{sec:analysis});
  \item describes how notes compose into balanced, range-proven transactions
        and how double spending is detected (Section~\ref{sec:tx});
  \item analyses the amortised issuance proof used by the prototype
        (Section~\ref{sec:batching}): it proves a soundness bound for the

  \item reports proof sizes, transaction sizes and measured timings of the

\end{itemize}

Section~\ref{sec:open} collects open problems, and Appendix~\ref{app:sigma}
develops the $\Sigma$-protocol for linear maps that both proofs of the scheme
instantiate.

\section{Background and Related Work}
\label{sec:background}

\subsection{Blind-signature eCash and Fedimint}

Chaum's untraceable payments~\cite{chaum83} introduced the pattern that all
later eCash follows: a user obtains a signature on a blinded message, unblinds
it, and later presents the signature, which the issuer cannot connect to the
blinded message it signed. Fedimint~\cite{fedimint} applies this pattern with
threshold BLS signatures~\cite{bls01,boldyreva03}: a federation of $n$
guardians holds Shamir shares of a signing key per denomination, a user
submits a blinded serial, and any $t$ guardians' signature shares combine into
a note. Values are public because the denomination is the key. A transaction
spends notes as inputs and requests new notes as outputs, and the federation
checks that the denominations balance. The scheme in this paper keeps the
federation, the threshold issuance and the transaction structure, and replaces
the per-denomination key by a single key over hidden attributes.

\subsection{Pointcheval--Sanders signatures and Coconut}

Camenisch--Lysyanskaya signatures~\cite{cl04} made it possible to sign
committed messages and to prove possession of a signature in zero knowledge,
the basis of anonymous credentials. Pointcheval and Sanders~\cite{ps16} gave a
much shorter scheme with the same features in type-3 pairing groups: a
signature is two elements of $\GG{1}$ regardless of the number of messages,
signing is linear in both the key and the messages, and signatures can be
re-randomised. Its security was first argued under an interactive LRSW-type
assumption~\cite{lrsw99} and later under the non-interactive
$q$-MSDH-1 assumption~\cite{ps18}. Coconut~\cite{coconut} observed that the
linearity in the key allows threshold issuance by Shamir sharing and Lagrange
interpolation in the exponent, provided all authorities use the same signature
base; it derives that base by hashing a commitment supplied by the user,
following the hash-to-base idea of BLS. Coconut carries the hidden attributes
to the authorities as ElGamal ciphertexts of $\K{m_j}\Go{B}$.

\subsection{Nym's variant}

Nym Technologies deploys Coconut credentials in its network~\cite{nym} and,
for its zk-nym bandwidth credentials, a compact divisible eCash scheme built on
the same signature~\cite{rial23,nymcode}. Their issuance protocol replaces the
ElGamal ciphertexts by Pedersen commitments $\Go{C_j} = \K{m_j}\Go{B} + \K{o_j}\Go{G_1}$
in the hashed base, with the verification key published in both source groups
so that the user can strip the blinding term with public information only.
This removes the user's ElGamal key pair and shortens the request. The scheme
of this paper follows Nym's issuance protocol and attribute layout but uses the
credential differently at spend time: Nym blinds the attribute term of the
verification equation with fresh randomness because it is not a nullifier,
whereas here that term is deliberately deterministic (Section~\ref{sec:spend}).

\subsection{Confidential amounts}

Hiding amounts behind Pedersen commitments~\cite{pedersen91} and balancing a
transaction by the homomorphic sum of its commitments is the Confidential
Transactions design~\cite{maxwell15}. Because commitments are over a prime
field, a balanced transaction can still create value through wrap-around
unless every output is proven to lie in a small range; Bulletproofs~\cite{bulletproofs}
provide such range proofs with size logarithmic in the bit length and
aggregatable across outputs without a trusted setup. We reuse both ideas and
bind the committed amount to the signed attribute with the issuance proof.

\subsection{Nullifiers and compact eCash}

Detecting double spending of an anonymous token by publishing a deterministic
function of a hidden secret, the \emph{nullifier}, goes back to compact
eCash~\cite{chl05} and is used by Zcash~\cite{zcash}. Our nullifier
$\Gt{K'} = \K{m_1}\Gt{X_1} + \K{m_2}\Gt{X_2}$ is the hidden-attribute part of the
PS verification equation itself, so it costs nothing extra to verify and is
tied to the signature by the pairing check rather than by an additional proof.

\subsection{Batch verification and amortised proofs}

Checking many linear relations at once through a random linear combination is
the small-exponents batch verification of Bellare, Garay and
Rabin~\cite{bgr98}. Applied inside a $\Sigma$-protocol it lets a prover answer
many instances of the same linear map with one response, which is the
amortisation used in Section~\ref{sec:batching}. Logarithmic-size alternatives
exist, notably the inner-product folding of Bulletproofs and compressed
$\Sigma$-protocols~\cite{acf21}; they trade prover and verifier work for size
and are not used here.

\section{Notation and Setting}
\label{sec:notation}

\subsection{Scalars, groups and the pairing}

Throughout, $\F := \mathbb{Z}/p\mathbb{Z}$ is the field of integers modulo the
prime $p$, the order of the BLS12-381 groups. Let $\GG{1}, \GG{2}, \GG{T}$ be the
BLS12-381 pairing groups, all of order $p$ and \emph{written additively}, and let
\[
  e : \GG{1} \times \GG{2} \to \GG{T}
\]
be the pairing. It is bilinear: for all $\K{a},\K{b} \in \F$,
$\Go{U} \in \GG{1}$ and $\Gt{W} \in \GG{2}$,
\[
  e(\K{a}\,\Go{U},\; \K{b}\,\Gt{W}) \;=\; \K{ab}\; \GT{e(\Go{U}, \Gt{W})} .
\]
Since each group has prime order $p$, scalar multiplication
$\F \times \GG{i} \to \GG{i}$, $(\K{\lambda}, \Go{U}) \mapsto \K{\lambda}\,\Go{U}$
makes every $\GG{i}$ a one-dimensional $\F$-vector space. All maps in this
document that send attributes and randomness to group elements are therefore
$\F$-\emph{linear maps}, and the whole scheme can be read in the language of
linear algebra. There is no efficient map from $\GG{1}$ to $\GG{2}$ or back
(type-3 pairing), which is what makes it safe to publish key material in both
groups.

\subsection{Generators and hash functions}

$\Go{G_1} \in \GG{1}$ and $\Gt{G_2} \in \GG{2}$ are fixed generators. All further
generators are derived by hashing domain-separation strings to the curve
(nothing-up-my-sleeve), so that nobody knows a discrete logarithm relation
between any two of them:
\begin{itemize}[nosep]
  \item $\Go{G_p}, \Go{H_p} \in \GG{1}$ -- Pedersen basis for \emph{amounts};
  \item $\Go{H_1}, \Go{H_2}, \Go{H_3} \in \GG{1}$ -- basis for the attribute commitment $\Go{C_m}$.
\end{itemize}
The generator $\Go{G_1}$ doubles as the blinding generator of all commitments
that the mint signs. This is not a coincidence: unblinding in
Section~\ref{sec:unblind} only works because the blinding generator of the
commitments is the same generator in which the mint's public key is published
in $\GG{1}$.

Two hash functions, modelled as random oracles, are used:
\[
  \Hg : \{0,1\}^* \to \GG{1} \qquad\text{and}\qquad \Hs : \{0,1\}^* \to \F .
\]
$\Hg$ derives the per-note signature base $\Go{B}$; $\Hs$ derives
Fiat--Shamir challenges and encodes the spend condition as a scalar. $\|$
denotes concatenation of canonical encodings.

\subsection{Keys}

For a single issuer, the secret key is a vector of four scalars,
\[
  \mathsf{sk} = (\K{x_0}, \K{x_1}, \K{x_2}, \K{x_3}) \in \F^4,
\]
one \emph{constant term} $\K{x_0}$ plus one scalar $\K{x_j}$ per attribute
$\K{m_j}$. The public key publishes each component in \emph{both} source groups:
\[
  \mathsf{pk} \;=\; \bigl(\;
    \underbrace{\{\Go{Y_j} = \K{x_j}\,\Go{G_1}\}_{j=0}^{3}}_{\text{in } \GG{1}\text{: used for unblinding}},\quad
    \underbrace{\{\Gt{X_j} = \K{x_j}\,\Gt{G_2}\}_{j=0}^{3}}_{\text{in } \GG{2}\text{: used for verification}}
  \;\bigr).
\]
In Coconut's notation $\Gt{X_0}$ is $\alpha$, $\Gt{X_j}$ is $\beta_j$ and
$\Go{Y_j}$ is Nym's $\beta_{g_1,j}$~\cite{nymcode}.
Section~\ref{sec:threshold} replaces the single issuer by a $t$-of-$n$
federation whose \emph{aggregate} key has exactly this shape.

\subsection{Assumptions}
\label{sec:assumptions}

The security arguments of Section~\ref{sec:analysis} rely on the following
standard assumptions, all believed to hold in BLS12-381.
\begin{description}[nosep,leftmargin=1.2em]
\item[DL.] The discrete-logarithm problem is hard in $\GG{1}$ and $\GG{2}$. It
  makes the Pedersen commitments binding: an opening of $\Go{P}$ to two
  different amounts yields the discrete logarithm of $\Go{H_p}$ to base $\Go{G_p}$.
\item[DDH / SXDH.] Decisional Diffie--Hellman is hard in $\GG{1}$ and in
  $\GG{2}$ separately (the symmetric external Diffie--Hellman assumption),
  which is plausible precisely because the pairing is type-3. It makes
  re-randomised signatures unlinkable and hides $\K{m_1}$ inside $\Gt{K'}$.
\item[PS unforgeability.] Pointcheval--Sanders signatures are existentially
  unforgeable under chosen-message attack. This holds under the interactive
  LRSW-type assumption of~\cite{ps16} or, for signatures with $q$ messages,
  under the $q$-MSDH-1 assumption of~\cite{ps18}. We note in
  Section~\ref{sec:sharedh} that the assumption presupposes a fresh base per
  signature.
\item[Random oracles.] $\Hg$ and $\Hs$ are modelled as random oracles. $\Hg$
  gives every note a base with unknown discrete logarithm; $\Hs$ makes the
  Fiat--Shamir transform sound.
\end{description}

\section{System Model and Security Goals}
\label{sec:model}

\subsection{Parties and threat model}

There are $n$ \emph{mints} (Fedimint guardians), each holding a share of the
federation's signing key, and any number of \emph{users}. A mint acts both as
an issuer, when it signs a blinded request, and as a verifier, when it checks a
spend as part of validating a transaction. Mints run a consensus protocol; we
treat it as a black box that delivers the same transactions in the same order
to every honest mint and bounds the size of a transaction.

An adversary may corrupt up to $t-1$ mints and any number of users, adaptively
but statically within one issuance. Corrupted parties collude and share all
state, including key shares. Honest mints run the protocol as specified and
keep their key shares secret. The network is under adversarial control; all
messages between users and mints are visible to the adversary. We do not model
denial of service.

\subsection{Syntax}

The scheme consists of the following algorithms, which
Section~\ref{sec:scheme} instantiates.
\begin{description}[nosep,leftmargin=1.2em]
\item[$\mathsf{KeyGen}(t,n)$] outputs an aggregate public key $\mathsf{pk}$,
  public key shares $\mathsf{pk}_1,\dots,\mathsf{pk}_n$ and secret key shares
  $\mathsf{sk}_1,\dots,\mathsf{sk}_n$.
\item[$\mathsf{Request}(\K{v},\auth)$] run by a user with amount $\K{v}$ and
  spend condition $\auth$; outputs a public request $\mathsf{req}$ and private
  state $\mathsf{st}$.
\item[$\mathsf{Sign}(\mathsf{sk}_i,\mathsf{req})$] run by mint $i$; verifies
  $\mathsf{req}$ and outputs a blinded signature share $\Go{\widetilde{\sigma}_i}$
  or $\bot$.
\item[$\mathsf{Finalize}(\mathsf{st},\{\Go{\widetilde{\sigma}_i}\}_{i\in S})$]
  run by the user with shares from a set $S$ of $t$ mints; outputs a note
  $\mathsf{note}$ or $\bot$.
\item[$\mathsf{Spend}(\mathsf{note})$] outputs a spend $\mathsf{sp}$ and the
  nullifier $\Gt{K'}$.
\item[$\mathsf{Verify}(\mathsf{pk},\mathsf{sp},\auth)$] outputs $0$ or $1$.
\end{description}
Amount commitments appear in both $\mathsf{req}$ and $\mathsf{sp}$ so that the
transaction layer (Section~\ref{sec:tx}) can balance them.

\subsection{Security goals}

\begin{description}[nosep,leftmargin=1.2em]
\item[Correctness.] A note obtained from $t$ honest mints on an honest request
  verifies, and its spend reveals the nullifier of that note.
\item[Unforgeability (balance).] No adversary corrupting fewer than $t$ mints
  can produce $k$ valid spends with pairwise distinct nullifiers whose committed
  amounts sum to more than the amounts of the notes issued to it by the honest
  mints. This covers creating notes from nothing, increasing a note's value,
  and spending a note more than once.
\item[Blindness.] The mints learn nothing about the attributes
  $(\K{m_1},\K{m_2},\K{m_3})$ from an issuance beyond what the range proof
  states.
\item[Unlinkability.] Given two spends and two issuance transcripts, an
  adversary, even one holding all key shares, cannot tell which spend came from
  which issuance better than by guessing.
\item[Double-spend detection.] Two spends of the same note have the same
  nullifier; two spends of different notes have different nullifiers except
  with negligible probability.
\item[Value confidentiality.] An observer of all transcripts learns nothing
  about a note's amount beyond the range proven at issuance and the balance
  relations of the transactions it appears in.
\end{description}

\section{The Scheme for a Single Note}
\label{sec:scheme}

This section presents the lifecycle of \emph{one} eCash note, first with a
single issuer and then with a federation of mints. Batching several notes into
one request is deferred to Section~\ref{sec:batching}; nothing in this section
depends on it.

\subsection{The underlying signature}
\label{sec:ps}

A Pointcheval--Sanders signature~\cite{ps16} on the attributes
$(\K{m_1},\K{m_2},\K{m_3})$ with base point $\Go{B} \in \GG{1}$ (Coconut's $h$) is the pair
$(\Go{B}, \Go{\sigma})$ with
\begin{equation}
  \Go{\sigma} \;=\; \Bigl(\K{x_0} + \sum_{j=1}^{3} \K{x_j}\,\K{m_j}\Bigr)\,\Go{B},
  \label{eq:ps}
\end{equation}
verified with the public key in $\GG{2}$ by the single pairing equation
\begin{equation}
  e\Bigl(\Go{B},\; \Gt{X_0} + \sum_{j=1}^{3} \K{m_j}\,\Gt{X_j}\Bigr) \;\eqq\; e(\Go{\sigma},\, \Gt{G_2}).
  \label{eq:psverify}
\end{equation}
Correctness is bilinearity: both sides equal
$\GT{e(\Go{B},\Gt{G_2})}$ raised to $\K{x_0} + \sum_j \K{x_j}\K{m_j}$.
Three properties of this signature carry the whole scheme.

\begin{whybox}[Why PS signatures]
\begin{enumerate}[nosep,leftmargin=*]
\item \textbf{Signing is linear in the key.} Equation~\eqref{eq:ps} is a
  linear function of $(\K{x_0},\dots,\K{x_3})$. Anything linear in the key can
  be Shamir-shared and interpolated in the exponent, which gives threshold
  issuance (Section~\ref{sec:threshold}).
\item \textbf{Signing is linear in the messages.} A commitment $\K{m_j}\Go{B} + \K{r_j}\Go{G_1}$
  can be fed into~\eqref{eq:ps} in place of $\K{m_j}\Go{B}$; the signer never
  sees $\K{m_j}$, and the extra term is removable. This gives blind issuance
  (Section~\ref{sec:blindsign}).
\item \textbf{Re-randomisable.} For any $\K{r} \neq 0$, $(\K{r}\Go{B}, \K{r}\Go{\sigma})$
  is an equally valid signature on the same messages, and is unlinkable to
  $(\Go{B},\Go{\sigma})$ under DDH in $\GG{1}$. This gives unlinkable spending
  (Section~\ref{sec:spend}).
\end{enumerate}
\end{whybox}

The base $\Go{B}$ must be different for every signature. If two signatures share
a base, their affine combinations are again valid signatures, on the
corresponding affine combination of the messages (Coconut, footnote~3
in~\cite{coconut}; see also Section~\ref{sec:sharedh}). In plain PS the signer
picks $\Go{B}$ at random, which a set of independent mints cannot do
consistently; Coconut instead derives $\Go{B}$ by hashing a commitment supplied
by the user, so that every mint computes the same $\Go{B}$ on its own.

\subsection{Requesting issuance}
\label{sec:request}

The user holds the attributes $(\K{m_1},\K{m_2},\K{m_3})$, samples the
randomness $\K{r_p}, \K{r_m}, \K{r_1}, \K{r_2}, \K{r_3}$ uniformly from $\F$,
and forms five elements of $\GG{1}$:
\begin{align}
  \Go{P} &= \K{m_1}\,\Go{G_p} + \K{r_p}\,\Go{H_p}
     && \annot{(Pedersen commitment to the amount)}{(amount commitment)} \label{eq:pc} \\
  \Go{C_m} &= \K{m_1}\,\Go{H_1} + \K{m_2}\,\Go{H_2} + \K{m_3}\,\Go{H_3} + \K{r_m}\,\Go{G_1}
     && \annot{(commitment to all attributes)}{(attribute commitment)} \label{eq:cm} \\
  \Go{B} &= \Hg(\Go{C_m})
     && \annot{(derived signature base)}{(signature base)} \label{eq:h} \\
  \Go{C_j} &= \K{m_j}\,\Go{B} + \K{r_j}\,\Go{G_1}
     && \annot{(blinded attributes, $j \in \{1,2,3\}$)}{(blinded attr., $j \in \{1,2,3\}$)} \label{eq:cj}
\end{align}
The issuance request consists of the statement
$\vv{C} = (\Go{P}, \Go{C_m}, \Go{C_1}, \Go{C_2}, \Go{C_3}) \in \GG{1}^5$, the
proof of Section~\ref{sec:issuanceproof}, and the range proof of
Section~\ref{sec:range}. The mint recomputes $\Go{B}$ from $\Go{C_m}$ itself;
it is not transmitted.

\begin{whybox}[What each element is for]
\begin{description}[nosep,leftmargin=1.2em]
\item[$\Go{P}$ -- the amount commitment.] Pedersen commitment in its own
  basis $(\Go{G_p},\Go{H_p})$: perfectly hiding because of $\K{r_p}$, binding
  under the discrete-logarithm assumption between $\Go{G_p}$ and $\Go{H_p}$. It is
  \emph{additively homomorphic}, $\Go{P}(\K{m},\K{r}) + \Go{P}(\K{m'},\K{r'}) = \Go{P}(\K{m+m'},\K{r+r'})$,
  which lets the transaction layer check that inputs and outputs balance
  without seeing the amounts. It is also the object the range proof
  (Section~\ref{sec:range}) is attached to. It is deliberately in a basis
  unrelated to the signature so that balance checking is independent of the
  credential.
\item[$\Go{C_m}$ -- the commitment behind $\Go{B}$.] A Pedersen vector
  commitment to all three attributes with randomness $\K{r_m}$. Its only
  purpose is to be hashed into $\Go{B}$. Because it is \emph{binding},
  $\Go{B}$ is a function of the attributes the user is about to get signed;
  because it is \emph{hiding}, the mint learns nothing from it; because
  $\K{r_m}$ is fresh, every request gets a fresh base even for identical
  attributes.
\item[$\Go{B}$ -- the signature base.] Neither party chooses it: the user
  cannot pick a base with a known relation to another note's base (which would
  enable the affine-combination forgery of Section~\ref{sec:ps}), and the mint
  does not have to pick anything, so all mints of a federation agree on
  $\Go{B}$ without communicating. This is the Coconut trick that turns PS into
  a threshold-friendly scheme.
\item[$\Go{C_j}$ -- the blinded attributes.] Pedersen commitments to each
  attribute \emph{in the base} $\Go{B}$ with blinding on $\Go{G_1}$. The base
  $\Go{B}$ is what the signature~\eqref{eq:ps} multiplies the attributes with,
  so the mint can apply its key directly to $\Go{C_j}$
  (Section~\ref{sec:blindsign}). The blinding generator $\Go{G_1}$ is what the
  public key $\Go{Y_j}$ is published in, so the blinding term the mint
  inadvertently signs, $\K{r_j}\K{x_j}\Go{G_1} = \K{r_j}\Go{Y_j}$, is computable by the user
  from public data. In the original Coconut these were ElGamal ciphertexts of
  $\K{m_j}\Go{B}$; Nym's commitments serve the same purpose with less data.
\end{description}
\end{whybox}

\subsection{The issuance proof}
\label{sec:issuanceproof}

The mint must be convinced that $\vv{C}$ is well formed before signing:
otherwise a user could, for instance, put one amount into $\Go{P}$ (and its
range proof) and a different amount into $\Go{C_1}$ (and the signature). Well-formedness
of $\vv{C}$ is exactly the statement that $\vv{C}$ lies in the image of the
linear map $\varphi_{\Go{B}} : \F^8 \to \GG{1}^5$,
\begin{equation}
  \ifafive \varphi_{\Go{B}}(\vv{w}) \else
  \varphi_{\Go{B}}(\K{m_1},\K{m_2},\K{m_3},\K{r_p},\K{r_m},\K{r_1},\K{r_2},\K{r_3}) \fi
  \;=\;
  \begin{pmatrix}
    \K{m_1}\,\Go{G_p} + \K{r_p}\,\Go{H_p} \\[2pt]
    \K{m_1}\,\Go{H_1} + \K{m_2}\,\Go{H_2} + \K{m_3}\,\Go{H_3} + \K{r_m}\,\Go{G_1} \\[2pt]
    \K{m_1}\,\Go{B} + \K{r_1}\,\Go{G_1} \\[2pt]
    \K{m_2}\,\Go{B} + \K{r_2}\,\Go{G_1} \\[2pt]
    \K{m_3}\,\Go{B} + \K{r_3}\,\Go{G_1}
  \end{pmatrix}
  \;=\;
  \begin{pmatrix} \Go{P} \\[2pt] \Go{C_m} \\[2pt] \Go{C_1} \\[2pt] \Go{C_2} \\[2pt] \Go{C_3} \end{pmatrix}
  = \vv{C}.
  \label{eq:phi}
\end{equation}
The witness, known only to the user and never transmitted, is
\[
  \vv{w} = (\K{m_1},\K{m_2},\K{m_3},\K{r_p},\K{r_m},\K{r_1},\K{r_2},\K{r_3}) \in \F^8 .
\]
Note that $\varphi_{\Go{B}}$ depends on $\Go{B}$, which the verifier recomputes
from the second component of $\vv{C}$; the map is fixed once $\Go{C_m}$ is.

The user proves knowledge of a preimage with the standard $\Sigma$-protocol
for linear maps (Appendix~\ref{app:sigma}; Schnorr's protocol generalised to a
vector-valued linear map),
made non-interactive with the Fiat--Shamir transform under the domain tag
$\dtag_{\mathrm{iss}} = {}$\texttt{FEDIMINT\_\allowbreak ECASH\_\allowbreak CHALLENGE\_\allowbreak ISSUANCE}:
\begin{equation}
\begin{aligned}
  \vv{\rho} &\sample \F^8, &
  \vv{R} &= \varphi_{\Go{B}}(\vv{\rho}) \in \GG{1}^5, \\
  \K{\gamma} &= \Hs\bigl(\dtag_{\mathrm{iss}} \,\|\, \vv{C} \,\|\, \vv{R}\bigr) \in \F, &
  \vv{s} &= \vv{\rho} + \K{\gamma}\,\vv{w} \in \F^8 .
\end{aligned}
  \label{eq:sigma}
\end{equation}
The proof is $(\vv{R}, \vv{s})$: five $\GG{1}$ elements and eight scalars,
$5 \cdot 48 + 8 \cdot 32 = 496$ bytes. The verifier recomputes $\Go{B}$ and
$\K{\gamma}$ and checks
\begin{equation}
  \varphi_{\Go{B}}(\vv{s}) \;\eqq\; \K{\gamma}\,\vv{C} + \vv{R}.
  \label{eq:sigmaverify}
\end{equation}

\begin{whybox}[Why this proves what we need]
\begin{description}[nosep,leftmargin=1.2em]
\item[Completeness.] By linearity,
  $\varphi_{\Go{B}}(\vv{s}) = \varphi_{\Go{B}}(\vv{\rho}) + \K{\gamma}\,\varphi_{\Go{B}}(\vv{w}) = \vv{R} + \K{\gamma}\vv{C}$.
\item[Knowledge (special soundness).] Two accepting transcripts with the same
  $\vv{R}$ and different challenges $\K{\gamma} \neq \K{\gamma'}$ give
  $\varphi_{\Go{B}}(\vv{s}-\vv{s}') = (\K{\gamma}-\K{\gamma'})\,\vv{C}$, so
  $(\K{\gamma}-\K{\gamma'})^{-1}(\vv{s}-\vv{s}')$ is a witness. A prover who can
  answer two challenges knows a preimage. In the random-oracle model
  Fiat--Shamir preserves this.
\item[Zero knowledge.] A simulator picks $\vv{s} \sample \F^8$ and
  $\K{\gamma} \sample \F$ first and sets $\vv{R} = \varphi_{\Go{B}}(\vv{s}) - \K{\gamma}\vv{C}$;
  the transcript is distributed exactly like a real one. The mint learns
  nothing about the attributes beyond the commitments, which are hiding.
\item[What the single witness buys us.] One witness vector serves all five
  equations, so the \emph{same} $\K{m_1}$ sits in $\Go{P}$, $\Go{C_m}$ and $\Go{C_1}$,
  and the same $\K{m_2},\K{m_3}$ sit in $\Go{C_m}$ and $\Go{C_2},\Go{C_3}$. Hence
  (i) the amount that is range-proven is the amount that gets signed
  (unforgeability of value), (ii) $\Go{B}$ really is derived from a commitment
  to the attributes being signed (the freshness argument for $\Go{B}$ holds),
  and (iii) the $\Go{C_j}$ are of the exact form~\eqref{eq:cj}, so the
  blinding term in the signature is exactly $\sum_j \K{r_j}\Go{Y_j}$ and
  nothing else gets signed. Hashing $\vv{C}$ into the challenge binds the proof
  to the statement; the domain tag prevents replaying a proof for $\psi$ of
  Section~\ref{sec:spend} against $\varphi_{\Go{B}}$.
\end{description}
\end{whybox}

\subsection{Range proof on the amount}
\label{sec:range}

The commitment $\Go{P}$ hides $\K{m_1}$ as an element of $\F$, and $\F$ wraps
around: a ``negative'' amount $-\K{v}$ is the field element $p - \K{v}$. Without
further constraints an adversary could commit to an out-of-range value and
satisfy a balance equation $\sum \Go{P}_{\mathrm{in}} = \sum \Go{P}_{\mathrm{out}}$
while creating value from nothing. The user therefore additionally proves that
the committed amount lies in an accepted interval, e.g.\ $0 \le \K{m_1} < 2^{64}$.
This work employs Bulletproofs~\cite{bulletproofs}, which give short
non-interactive range proofs over Pedersen commitments without a trusted setup,
with proof size logarithmic in the bit length and aggregatable across several
commitments. Because the issuance proof ties the $\K{m_1}$ in $\Go{P}$ to the
$\K{m_1}$ in the signature, the range proof on $\Go{P}$ carries over to the
signed amount.

\subsection{Blind signing}
\label{sec:blindsign}

A mint that has verified the proofs recomputes $\Go{B} = \Hg(\Go{C_m})$ and
applies its key to the request as if the $\Go{C_j}$ were the attributes:
\begin{equation}
  \Go{\widetilde{\sigma}}
  \;=\; \K{x_0}\,\Go{B} + \sum_{j=1}^{3} \K{x_j}\,\Go{C_j}
  \;=\; \underbrace{\Bigl(\K{x_0} + \sum_{j=1}^{3} \K{x_j}\,\K{m_j}\Bigr)\Go{B}}_{\text{PS signature } \Go{\sigma}\text{, eq.~\eqref{eq:ps}}}
      \;+\; \underbrace{\sum_{j=1}^{3} \K{r_j}\,\bigl(\K{x_j}\,\Go{G_1}\bigr)}_{\text{blinding term } = \sum_j \K{r_j}\Go{Y_j}} .
  \label{eq:blindsign}
\end{equation}
The expansion is just~\eqref{eq:cj} substituted into the first expression. The
mint never sees $\K{m_j}$; it sees $\Go{B}$, the $\Go{C_j}$ and the proof, all
of which are independent of the attributes by the hiding property and zero
knowledge.

\subsection{Unblinding and verification}
\label{sec:unblind}

The blinding term in~\eqref{eq:blindsign} is a linear combination of the
$\GG{1}$ public key components with coefficients the user chose, so the user
removes it from public information only:
\begin{equation}
  \Go{\sigma} \;=\; \Go{\widetilde{\sigma}} - \sum_{j=1}^{3} \K{r_j}\,\Go{Y_j},
  \label{eq:unblind}
\end{equation}
and then checks $(\Go{B},\Go{\sigma})$ against the $\GG{2}$ key with the PS
equation~\eqref{eq:psverify}. This is where the choice of $\Go{G_1}$ as the
blinding generator in~\eqref{eq:cj} is essential: with any other blinding
generator the user would need $\K{x_j}$ to cancel the term. The pair
$(\Go{B},\Go{\sigma})$ together with $(\K{m_1},\K{m_2},\auth)$ is the eCash note.

\subsection{Threshold issuance}
\label{sec:threshold}

Nothing above requires a single issuer, because~\eqref{eq:blindsign} is
$\F$-linear in the secret key $(\K{x_0},\dots,\K{x_3})$. The standard
threshold-BLS transformation~\cite{boldyreva03} therefore applies
component-wise, with Shamir sharing~\cite{shamir79} of each key component.

\paragraph{Key sharing.}
Each $\K{x_j}$ is Shamir-shared: pick random polynomials $f_j \in \F[X]$ of
degree at most $t-1$ with $f_j(0) = \K{x_j}$, and give mint
$i \in \{1,\dots,n\}$ the key share
\[
  \mathsf{sk}_i = \bigl(\K{f_0(i)}, \K{f_1(i)}, \K{f_2(i)}, \K{f_3(i)}\bigr) \in \F^4,
\]
with public key shares $\Go{Y_{i,j}} = \K{f_j(i)}\,\Go{G_1}$ and
$\Gt{X_{i,j}} = \K{f_j(i)}\,\Gt{G_2}$. The aggregate public key is
$\Go{Y_j} = \K{f_j(0)}\,\Go{G_1}$, $\Gt{X_j} = \K{f_j(0)}\,\Gt{G_2}$, i.e.\ exactly
the single-issuer key of Section~\ref{sec:notation}. Fewer than $t$ shares
reveal nothing about $\K{x_j}$.

\paragraph{Share signing and share verification.}
Every mint runs Section~\ref{sec:blindsign} with its own share,
\[
  \Go{\widetilde{\sigma}_i} \;=\; \K{f_0(i)}\,\Go{B} + \sum_{j=1}^{3} \K{f_j(i)}\,\Go{C_j},
\]
and the user unblinds each share with the mint's $\GG{1}$ key share,
$\Go{\sigma_i} = \Go{\widetilde{\sigma}_i} - \sum_j \K{r_j}\,\Go{Y_{i,j}}$, then
verifies it with~\eqref{eq:psverify} against $\Gt{X_{i,j}}$. A mint that
returns garbage is identified immediately and simply left out.

\paragraph{Aggregation.}
Let $S$ be a set of $t$ mint indices whose shares verified. The federation
signature is the Lagrange combination at $0$,
\begin{equation}
  \Go{\sigma} \;=\; \sum_{i \in S} \K{\lambda_i}\,\Go{\sigma_i},
  \qquad
  \K{\lambda_i} \;=\; \prod_{\substack{k \in S \\ k \neq i}} \frac{k}{k - i} \pmod p .
  \label{eq:lagrange}
\end{equation}
Since $\Go{\sigma_i} = \bigl(f_0(i) + \sum_j \K{m_j} f_j(i)\bigr)\,\Go{B}$ and
$\K{\lambda} \mapsto \K{\lambda}\,\Go{B}$ is linear, the sum evaluates the
polynomial $f_0 + \sum_j \K{m_j} f_j$ at $0$ inside the group, which is exactly
the single-issuer signature~\eqref{eq:ps}. Everything downstream is unchanged
and verifies against the aggregate key.

\subsection{Spending}
\label{sec:spend}

To spend, the user must show the mint a valid signature on a note without
letting the mint connect it to the issuance it came from, while still letting
the mint (i) check the amount against the transaction balance and (ii) detect
a second spend of the same note.

\paragraph{Re-randomisation.}
The user samples $\K{r}, \K{r'} \sample \F$ and forms
\begin{equation}
  (\Go{B'},\; \Go{\sigma'},\; \Gt{V}) \;=\; \bigl(\K{r}\,\Go{B},\;\; \K{r}\,\Go{\sigma} + \K{r}\K{r'}\,\Go{B},\;\; \K{r'}\,\Gt{G_2}\bigr).
  \label{eq:rerand}
\end{equation}
The pair $(\K{r}\Go{B}, \K{r}\Go{\sigma})$ is the PS re-randomisation of
Section~\ref{sec:ps}: fresh group elements, unlinkable to $(\Go{B},\Go{\sigma})$
under DDH in $\GG{1}$. The $\K{r'}$ terms are inherited from Coconut's
$(\kappa,\nu)$ and are discussed in Section~\ref{sec:V}.

\paragraph{Shown elements.}
Along with $(\Go{B'},\Go{\sigma'},\Gt{V})$ and the authentication data
$\auth$ the user sends
\begin{equation}
  \Go{P'} = \K{m_1}\,\Go{G_p} + \K{r'_p}\,\Go{H_p} \in \GG{1},
  \qquad
  \Gt{K'} = \K{m_1}\,\Gt{X_1} + \K{m_2}\,\Gt{X_2} \in \GG{2},
  \label{eq:spendelems}
\end{equation}
where $\K{r'_p} \sample \F$ is \emph{fresh} commitment randomness, together with a
second Fiat--Shamir $\Sigma$-proof (tag
$\dtag_{\mathrm{sp}} = {}$\texttt{FEDIMINT\_\allowbreak ECASH\_\allowbreak CHALLENGE\_\allowbreak SPEND}) of knowledge of
$(\K{m_1},\K{m_2},\K{r'_p})$ for the linear map
\begin{equation}
\begin{aligned}
  \psi &: \F^3 \to \GG{1} \times \GG{2}, \\
  \psi(\K{m_1}, \K{m_2}, \K{r'_p}) &= \bigl(\, \K{m_1}\,\Go{G_p} + \K{r'_p}\,\Go{H_p},\;\; \K{m_1}\,\Gt{X_1} + \K{m_2}\,\Gt{X_2} \,\bigr) = (\Go{P'}, \Gt{K'}).
\end{aligned}
  \label{eq:psi}
\end{equation}
The protocol is the same as in~\eqref{eq:sigma} with $\psi$ in place of
$\varphi_{\Go{B}}$ and witness $(\K{m_1},\K{m_2},\K{r'_p})$; the prototype
transmits the challenge instead of the commitment $(\Go{R_{P'}},\Gt{R_K})$, so a
spend proof is four scalars ($128$ bytes), and the verifier recomputes the
commitment as $\psi(\vv{s}) - \K{\gamma}\,(\Go{P'},\Gt{K'})$.

\paragraph{Verification.}
The mint recomputes $\K{m_3} = \Hs(\auth)$, requires $\K{m_3} \neq 0$ and
$\Go{B'} \neq 0$, verifies the $\psi$-proof, checks that $\Gt{K'}$ has not been
seen before, and finally checks the signature:
\begin{equation}
  e\bigl(\Go{B'},\; \Gt{X_0} + \Gt{K'} + \K{m_3}\,\Gt{X_3} + \Gt{V}\bigr) \;\eqq\; e(\Go{\sigma'},\, \Gt{G_2}).
  \label{eq:spendverify}
\end{equation}
Expanding both sides shows why it holds. Write
$\K{z} := \K{x_0} + \K{x_1}\K{m_1} + \K{x_2}\K{m_2} + \K{x_3}\K{m_3}$, so that
$\Go{\sigma} = \K{z}\,\Go{B}$ and
$\Gt{X_0} + \Gt{K'} + \K{m_3}\Gt{X_3} = \K{z}\,\Gt{G_2}$. Then
\begin{align*}
  \text{LHS} &= e\bigl(\K{r}\Go{B},\; (\K{z} + \K{r'})\,\Gt{G_2}\bigr)
             = \K{r}(\K{z}+\K{r'})\,\GT{e(\Go{B},\Gt{G_2})}, \\
  \text{RHS} &= e\bigl(\K{r}\K{z}\,\Go{B} + \K{r}\K{r'}\,\Go{B},\; \Gt{G_2}\bigr)
             = \K{r}(\K{z}+\K{r'})\,\GT{e(\Go{B},\Gt{G_2})}.
\end{align*}
The equation is the PS verification~\eqref{eq:psverify} with the hidden part
$\K{m_1}\Gt{X_1} + \K{m_2}\Gt{X_2}$ of the message supplied as the single
element $\Gt{K'}$, the revealed part $\K{m_3}\Gt{X_3}$ recomputed by the mint,
and the $\K{r'}$ terms cancelling on both sides.

\begin{whybox}[What each shown element achieves]
\begin{description}[nosep,leftmargin=1.2em]
\item[$(\Go{B'},\Go{\sigma'})$ -- unforgeability, unlinkability.] A valid
  re-randomised PS signature proves the federation signed \emph{some}
  attributes; fresh randomness makes the pair independent of the issuance
  transcript.
\item[$\Gt{K'}$ -- the nullifier and the hidden message.] It supplies the
  hidden attributes to the verification equation without revealing them, and
  it is \emph{deterministic} in $(\K{m_1},\K{m_2})$: spending the same note
  twice produces the same $\Gt{K'}$, so the mints keep a set of seen $\Gt{K'}$
  and reject repeats. The random $\K{m_2}$ makes $\Gt{K'}$ unique per note and,
  since $\K{m_2}$ was only ever seen blinded, unlinkable to issuance. Its
  soundness rests on the $\psi$-proof: a spender must \emph{know}
  $(\K{m_1},\K{m_2})$ behind $\Gt{K'}$, so $\Gt{K'}$ cannot be re-randomised into
  a fresh nullifier for the same note.
\item[$\Go{P'}$ -- confidential amount at spend time.] A fresh Pedersen
  commitment to the same amount, in the balance-check basis, with new
  randomness so it is unlinkable to $\Go{P}$. The $\psi$-proof ties the
  $\K{m_1}$ in $\Go{P'}$ to the $\K{m_1}$ in $\Gt{K'}$, and~\eqref{eq:spendverify}
  ties the $\K{m_1}$ in $\Gt{K'}$ to the signature. So the amount the
  transaction layer balances with is the amount the federation signed, which is
  the amount that was range-proven at issuance.
\item[$\K{m_3}$, $\auth$ -- the spend condition.] $\K{m_3}$ is baked into
  $\Go{\sigma}$, so only a spender who can present the committed $\auth$ makes
  \eqref{eq:spendverify} hold. Revealing $\auth$ does not link the spend to
  issuance because the mint only saw $\K{m_3}$ blinded. Requiring
  $\K{m_3} \neq 0$ excludes the degenerate case in which the third attribute
  contributes nothing to the signature.
\end{description}
\end{whybox}

\subsubsection{On the role of \texorpdfstring{$\Gt{V}$}{V}}
\label{sec:V}

In Coconut the spender shows $\kappa = \Gt{X_0} + \sum_j \K{m_j}\Gt{X_j} + \K{r'}\Gt{G_2}$
and $\nu = \K{r'}\Go{B'}$, and the verifier checks
$e(\Go{B'},\kappa) = e(\Go{\sigma'} + \nu, \Gt{G_2})$. The fresh $\K{r'}$ in
$\kappa$ is what hides the attributes there. In this scheme $\Gt{V} = \K{r'}\Gt{G_2}$
plays the part of $\kappa$'s blinding term and $\K{r}\K{r'}\Go{B}$ inside
$\Go{\sigma'}$ plays the part of $\nu$. However, $\Gt{K'}$ is deliberately
\emph{not} blinded, because it has to be a deterministic nullifier; and
$e(\Go{B'},\Gt{V}) = e(\K{r}\K{r'}\Go{B},\Gt{G_2})$ is computable by anyone from
the shown data, so an observer can cancel the $\K{r'}$ contribution from
$e(\Go{\sigma'},\Gt{G_2})$ and recover the same $\GG{T}$ values as if
$\K{r'} = 0$. Under this reading $\Gt{V}$ adds $96$ bytes and one scalar
multiplication but no additional hiding; the unlinkability of a spend rests on
the re-randomisation by $\K{r}$ and on the fresh $\K{r'_p}$. Whether $\Gt{V}$
should be kept is an open question (Section~\ref{sec:open}).

\section{Transactions}
\label{sec:tx}

A note on its own is a credential; eCash arises when notes are spent and
re-issued inside transactions validated by the federation. This section
describes the intended transaction layer. It is not part of the prototype, but
the scheme's elements were chosen for it.

\subsection{Structure and balance}

A transaction has $a$ inputs, each a spend $\mathsf{sp}_k$ of
Section~\ref{sec:spend} carrying an amount commitment $\Go{P'_k}$, and $b$
outputs, each an issuance request of Section~\ref{sec:request} carrying an
amount commitment $\Go{P_\ell}$, together with a public fee $\K{f} \ge 0$. The
spender additionally reveals the \emph{excess blinding}
\begin{equation}
  \K{\delta} \;=\; \sum_{k=1}^{a} \K{r'_{p,k}} - \sum_{\ell=1}^{b} \K{r_{p,\ell}} \;\in \F,
  \label{eq:excess}
\end{equation}
and the mints check
\begin{equation}
  \sum_{k=1}^{a} \Go{P'_k} \;\eqq\; \sum_{\ell=1}^{b} \Go{P_\ell} + \K{f}\,\Go{G_p} + \K{\delta}\,\Go{H_p}.
  \label{eq:balance}
\end{equation}
By the homomorphism of Pedersen commitments, \eqref{eq:balance} holds if and
only if $\sum_k \K{m_{1,k}} = \sum_\ell \K{m_{1,\ell}} + \K{f}$ in $\F$ or the
spender has found a discrete-logarithm relation between $\Go{G_p}$ and
$\Go{H_p}$. Revealing $\K{\delta}$ leaks nothing about the individual amounts
because each $\K{r_{p,\ell}}$ is uniform. Peg-ins and peg-outs are the cases
$a = 0$ and $b = 0$ respectively, with the on-chain amount taking the place of
$\K{f}$ as a public term; their Bitcoin-side handling is unchanged from
Fedimint and not discussed here.

\subsection{Range proofs}

Equation~\eqref{eq:balance} is over $\F$, so it is satisfied by an output
committing to $2^{64}$ and another committing to $p - 2^{64} + \K{v}$. Every
output therefore carries a Bulletproof that its amount lies in $[0, 2^{64})$;
the $b$ proofs aggregate into one of size $O(\log b)$. Inputs need no range
proof: their amounts were range-proven when they were issued, and the issuance
proof~\eqref{eq:phi} ties the range-proven commitment to the signed attribute,
while the spend proof~\eqref{eq:psi} and the pairing
check~\eqref{eq:spendverify} tie the signed attribute to $\Go{P'_k}$. This
chain is exactly what the shared-base weakness of Section~\ref{sec:sharedh}
breaks, because it lets a user obtain a signature on an amount that was never
range-proven.

\subsection{Validation and the nullifier set}

To validate a transaction, every mint
\begin{enumerate}[nosep]
  \item verifies each input with $\mathsf{Verify}$, i.e.\ the $\psi$-proof and
        the pairing check~\eqref{eq:spendverify};
  \item checks that no input nullifier $\Gt{K'_k}$ is in the set $N$ of
        nullifiers seen so far, and that the $a$ input nullifiers are pairwise
        distinct;
  \item verifies the issuance proof and the range proof of the outputs;
  \item checks the balance~\eqref{eq:balance}.
\end{enumerate}
If all checks pass the transaction is accepted by consensus, every mint adds
the input nullifiers to $N$ and signs the outputs with its key share. The set
$N$ grows by $96$ bytes per spent note and is the only state the scheme needs
beyond the key shares; it can be pruned once a key is retired.

\subsection{Offline spending}

Steps 1, 3 and 4 need only the aggregate public key, so a payee can check a
payment without the federation. Only step 2 needs the shared state $N$, so an
offline payee accepts the risk that the same note is spent elsewhere before the
transaction reaches the federation. This is the usual trade-off of offline
eCash; the scheme does not identify double spenders after the fact, it only
rejects the second spend.

\section{Batching Issuance Requests}
\label{sec:batching}

A naive approach to requesting several notes at once repeats
Section~\ref{sec:request} per note. The proof alone is then $496$ bytes per
note, and together with Fedimint's consensus message limit of $64$\,KB this
severely restricts how many notes a single transaction can issue. Several
techniques exist to combine multiple $\Sigma$-protocol instances into one
compact proof: folding as used by Bulletproofs for non-linear relations, or
amortisation for parallel instances of the same linear relation. The latter is
used here. There are still open discussions concerning the security of the
protocol when batching is applied, both for the proofs and for the credential
scheme itself; see Section~\ref{sec:sharedh}.

\subsection{Batched issuance proof}
\label{sec:batchproof}

Suppose the user requests $n$ notes, $i = 1,\dots,n$, with witnesses
$\vv{w}_i \in \F^8$ and statements
\[
  \vv{C}_i = (\Go{P_i}, \Go{C_{m,i}}, \Go{C_{1,i}}, \Go{C_{2,i}}, \Go{C_{3,i}}) \in \GG{1}^5 .
\]
The amortised protocol sums $n$ instances of~\eqref{eq:sigma}
into a single response, which only works if all instances use the \emph{same}
linear map. Since $\varphi_{\Go{B}}$ depends on $\Go{B}$, the batch shares one
base derived from all attribute commitments of the batch:
\begin{equation}
  \Go{B} \;=\; \Hg\bigl(\Go{C_{m,1}} \,\|\, \Go{C_{m,2}} \,\|\, \cdots \,\|\, \Go{C_{m,n}}\bigr),
  \qquad
  \varphi_{\Go{B}}(\vv{w}_i) = \vv{C}_i \quad \text{for all } i .
  \label{eq:batchh}
\end{equation}
For $n = 1$ this coincides with~\eqref{eq:h}. The prover samples one nonce
vector per instance, commits to their sum, derives one challenge \emph{per
instance}, and sums the responses:
\begin{align}
  \vv{\rho}_i &\sample \F^8, \qquad \vv{R}_i = \varphi_{\Go{B}}(\vv{\rho}_i), \qquad
  \vv{R} = \sum_{i=1}^{n} \vv{R}_i \;\in \GG{1}^5, \label{eq:batchR} \\
  \K{\gamma_i} &= \Hs\bigl(\dtag_{\mathrm{iss}} \,\|\, \vv{C}_1 \,\|\, \cdots \,\|\, \vv{C}_n \,\|\, \vv{R} \,\|\, i\bigr) \;\in \F, \label{eq:batchc} \\
  \vv{s} &= \sum_{i=1}^{n} \bigl(\vv{\rho}_i + \K{\gamma_i}\,\vv{w}_i\bigr) \;\in \F^8 . \label{eq:batchs}
\end{align}
The prover sends $(\vv{R}, \vv{s})$, again $496$ bytes regardless of $n$, along
with the statements $\vv{C}_1,\dots,\vv{C}_n$. The verifier recomputes
$\Go{B}$ from~\eqref{eq:batchh} and the $\K{\gamma_i}$ from~\eqref{eq:batchc} and
checks
\begin{equation}
  \varphi_{\Go{B}}(\vv{s}) \;\eqq\; \sum_{i=1}^{n} \K{\gamma_i}\,\vv{C}_i + \vv{R}.
  \label{eq:batchverify}
\end{equation}

\begin{whybox}[Why the batched proof works]
\begin{description}[nosep,leftmargin=1.2em]
\item[Completeness.] Linearity of $\varphi_{\Go{B}}$ applied to~\eqref{eq:batchs}:
  $\varphi_{\Go{B}}(\vv{s}) = \sum_i \varphi_{\Go{B}}(\vv{\rho}_i) + \sum_i \K{\gamma_i}\,\varphi_{\Go{B}}(\vv{w}_i) = \vv{R} + \sum_i \K{\gamma_i}\vv{C}_i$.
  This step is exactly where all instances must share $\varphi_{\Go{B}}$, i.e.\
  share $\Go{B}$.
\item[Soundness.] Lemma~\ref{lem:batch} below: if any $\vv{C}_i$ is not in the
  image of $\varphi_{\Go{B}}$, the check~\eqref{eq:batchverify} passes with
  probability at most $1/p$ over the choice of $\K{\gamma_i}$ alone. Including
  the index $i$ in the hash gives each instance its own independent challenge,
  which the lemma needs.
\item[Zero knowledge.] Unchanged: $\vv{s}$ is a sum of uniformly random
  $\vv{\rho}_i$ plus witness terms, hence uniform.
\end{description}
\end{whybox}

\begin{lemma}[Soundness of the batched check]
\label{lem:batch}
Let $\varphi : \F^8 \to \GG{1}^5$ be linear, let $\vv{C}_1,\dots,\vv{C}_n \in \GG{1}^5$
and $\vv{R} \in \GG{1}^5$ be fixed, and let $\K{\gamma_1},\dots,\K{\gamma_n}$ be
independent and uniform in $\F$. If $\vv{C}_j \notin \operatorname{im}\varphi$ for
some $j$, then the probability that there exists any $\vv{s} \in \F^8$ with
$\varphi(\vv{s}) = \sum_i \K{\gamma_i}\vv{C}_i + \vv{R}$ is at most $1/p$.
\end{lemma}
\begin{proof}
Fix all $\K{\gamma_i}$ with $i \ne j$ and write
$\Go{D} := \vv{R} + \sum_{i \ne j} \K{\gamma_i}\vv{C}_i$. A response exists iff
$\Go{D} + \K{\gamma_j}\vv{C}_j \in \operatorname{im}\varphi$. If this held for two
values $\K{\gamma_j} \ne \K{\gamma'_j}$, then, $\operatorname{im}\varphi$ being a
subspace, $(\K{\gamma_j}-\K{\gamma'_j})\vv{C}_j \in \operatorname{im}\varphi$ and
hence $\vv{C}_j \in \operatorname{im}\varphi$, a contradiction. So at most one
value of $\K{\gamma_j}$ admits a response, and it is hit with probability
$1/p$.
\end{proof}

In the random-oracle model the $\K{\gamma_i}$ of~\eqref{eq:batchc} are
independent and uniform once $\vv{C}_1,\dots,\vv{C}_n$ and $\vv{R}$ are fixed,
so a prover who tries $q$ hash queries succeeds on a false statement with
probability at most $q/p$. Knowledge of each individual witness follows from
$n+1$ accepting transcripts with affinely independent challenge vectors, which
a forking argument extracts; the linear system they define is triangular and
yields a preimage of every $\vv{C}_i$.

Range proofs batch independently: Bulletproofs aggregate the $n$ commitments
$\Go{P_1},\dots,\Go{P_n}$ into one proof of size logarithmic in $n$.

\subsection{Blind signing a batch}

Each mint verifies the batched proof once and then signs every note of the
batch with the \emph{shared} base,
$\Go{\widetilde{\sigma}_i} = \K{x_0}\,\Go{B} + \sum_j \K{x_j}\,\Go{C_{j,i}}$,
exactly as in~\eqref{eq:blindsign}; unblinding, share verification,
aggregation and spending are per note and unchanged from
Section~\ref{sec:scheme}. Note that after Section~\ref{sec:spend} the notes of
one batch are shown with independent re-randomisations $\K{r}\Go{B}$, so the
shared base is not visible at spend time.

\subsection{The cost of a shared base}
\label{sec:sharedh}

Sharing $\Go{B}$ across a batch is what makes~\eqref{eq:batchverify} possible,
but it removes the guarantee of Section~\ref{sec:ps} that every signature has
its own base, and PS unforgeability is only claimed for fresh bases. All notes
of a batch are PS signatures on the same $\Go{B}$, and PS signatures on a
common base are closed under affine combination: for any scalars
$\K{\lambda_i}$ with $\sum_i \K{\lambda_i} = 1$,
\begin{equation}
  \sum_{i} \K{\lambda_i}\,\Go{\sigma_i}
  \;=\; \Bigl(\K{x_0} + \sum_{j=1}^{3} \K{x_j} \sum_i \K{\lambda_i}\,\K{m_{j,i}}\Bigr)\,\Go{B}
  \label{eq:affine}
\end{equation}
is a valid signature on the attribute vector $\sum_i \K{\lambda_i}\,\vv{m}_i$.
This is the forgery Coconut's footnote~3 warns about~\cite{coconut}.

\paragraph{The attack end to end.} A user requests two notes in one batch with
amounts $\K{v_1} \ne \K{v_2}$, both range-proven, and the same spend condition
$\auth$, so $\K{m_{3,1}} = \K{m_{3,2}}$. After aggregation the user holds
$(\Go{B},\Go{\sigma_1})$ and $(\Go{B},\Go{\sigma_2})$. For any target amount
$\K{v^*}$ the user picks $\K{\lambda} = (\K{v^*} - \K{v_2})/(\K{v_1} - \K{v_2})$
and forms $\Go{\sigma^*} = \K{\lambda}\Go{\sigma_1} + (1-\K{\lambda})\Go{\sigma_2}$,
a valid signature on amount $\K{v^*}$, serial secret
$\K{\lambda}\K{m_{2,1}} + (1-\K{\lambda})\K{m_{2,2}}$ and the known spend
condition. The serial is fresh, so its nullifier is not in $N$. The user spends
$\Go{\sigma^*}$ as the single input of a transaction with $\K{v^*}$ in
$\Go{P'}$, and requests outputs totalling $\K{v^*}$, each with an honest range
proof. Every check of Section~\ref{sec:tx} passes: inputs are not range-proven,
and nothing else constrains $\K{v^*}$. The user has created $\K{v^*}$ units
from nothing, and the two original notes remain spendable.

The attack needs only two notes with equal $\K{m_3}$, which the user controls,
so it cannot be prevented on the user side; it is mitigated only by preventing
two signatures on one base, by making the amount of an input range-proven again
at spend time, or by both.

\subsection{Mitigation: per-note bases with partially amortised responses}
\label{sec:mitigation}

The affine combination~\eqref{eq:affine} is only possible because the rows of
$\varphi_{\Go{B}}$ that involve the base are shared. The rows for $\Go{P}$ and
$\Go{C_m}$ use fixed generators and can be batched by the lemma for any set of
notes; the rows for $\Go{C_1},\Go{C_2},\Go{C_3}$ are the only ones that need a
common map. Giving every note its own base $\Go{B_i} = \Hg(\Go{C_{m,i}})$ as in
the single-note scheme and batching only what can be batched yields the
following protocol. Write the witness of note $i$ as
$\vv{w}_i = (\vv{m}_i, \K{r_{p,i}}, \K{r_{m,i}}, \vv{r}_i)$ with
$\vv{m}_i = (\K{m_{1,i}},\K{m_{2,i}},\K{m_{3,i}})$ and $\vv{r}_i = (\K{r_{1,i}},\K{r_{2,i}},\K{r_{3,i}})$.
\begin{enumerate}[nosep]
  \item The prover samples $\vv{\rho}_i \sample \F^8$ for every note and
        computes the commitments $\vv{R}_i = \varphi_{\Go{B_i}}(\vv{\rho}_i)$.
        Let $\Go{R_P} = \sum_i \vv{R}_{i,1}$ and $\Go{R_{C_m}} = \sum_i \vv{R}_{i,2}$
        be the sums of the first two rows.
  \item Challenges: $\K{\gamma_i} = \Hs(\dtag_{\mathrm{iss}} \,\|\, \vv{C}_1 \,\|\cdots\|\, \vv{C}_n \,\|\, \Go{R_P} \,\|\, \Go{R_{C_m}} \,\|\, \vv{R}_{1,3..5} \,\|\cdots\|\, \vv{R}_{n,3..5} \,\|\, i)$.
  \item Responses: per note
        $\vv{s}_{m,i} = \vv{\rho}_{m,i} + \K{\gamma_i}\vv{m}_i \in \F^3$ and
        $\vv{s}_{r,i} = \vv{\rho}_{r,i} + \K{\gamma_i}\vv{r}_i \in \F^3$;
        shared
        $\K{s_p} = \sum_i (\K{\rho_{p,i}} + \K{\gamma_i}\K{r_{p,i}})$ and
        $\K{s_m} = \sum_i (\K{\rho_{m,i}} + \K{\gamma_i}\K{r_{m,i}})$.
  \item The proof is $(\K{\gamma_1}, \{\vv{s}_{m,i}, \vv{s}_{r,i}\}_i, \K{s_p}, \K{s_m})$:
        the commitments are not sent, the verifier recomputes them from the
        responses and the challenges and re-derives the hash. Since all
        $\K{\gamma_i}$ come from one hash state, sending $\K{\gamma_1}$ suffices
        to check the whole derivation.
\end{enumerate}
The verifier recomputes $\Go{B_i}$ and checks the two batched rows and the
$3n$ per-note rows:
\begin{align}
  \textstyle\sum_i \K{s_{m_1,i}}\,\Go{G_p} + \K{s_p}\,\Go{H_p} &= \Go{R_P} + \textstyle\sum_i \K{\gamma_i}\,\Go{P_i}, \\
  \textstyle\sum_i \bigl(\K{s_{m_1,i}}\Go{H_1} + \K{s_{m_2,i}}\Go{H_2} + \K{s_{m_3,i}}\Go{H_3}\bigr) + \K{s_m}\,\Go{G_1} &= \Go{R_{C_m}} + \textstyle\sum_i \K{\gamma_i}\,\Go{C_{m,i}}, \\
  \K{s_{m_j,i}}\,\Go{B_i} + \K{s_{r_j,i}}\,\Go{G_1} &= \vv{R}_{i,2+j} + \K{\gamma_i}\,\Go{C_{j,i}} \qquad (i \le n,\; j \le 3).
\end{align}
Soundness: the per-note rows are ordinary $\Sigma$-protocol instances, so two
transcripts per note extract $\vv{m}_i$ and $\vv{r}_i$; the batched rows then
satisfy Lemma~\ref{lem:batch}, and because the same responses $\K{s_{m_j,i}}$
appear in both, the extracted $\K{m_{1,i}}$ is the amount in $\Go{P_i}$ as well
as in $\Go{C_{1,i}}$. Zero knowledge is as before. Every note is signed on its
own base $\Go{B_i}$, so~\eqref{eq:affine} no longer applies and the
single-note analysis of Section~\ref{sec:analysis} carries over unchanged.

The proof has $6n + 3$ scalars, about $192n + 96$ bytes, against $496$ bytes
for the fully amortised proof and $496n$ bytes for $n$ independent proofs. The
mints perform $3n$ additional small multi-scalar multiplications. For the
$100$-note example of Section~\ref{sec:perf} the issuance proof grows from
$0.5$\,KB to $19.3$\,KB. Whether this is acceptable, or whether a
logarithmic-size compressed $\Sigma$-protocol~\cite{acf21} should replace it,
is left open. The prototype implements the fully amortised variant of
Section~\ref{sec:batchproof}; until it is replaced, the batched issuance must be
regarded as insecure.

\section{Security Analysis}
\label{sec:analysis}

We argue each goal of Section~\ref{sec:model} for the single-note scheme of
Section~\ref{sec:scheme} and for batching with the mitigation of
Section~\ref{sec:mitigation}. The arguments are sketches in the style of
Coconut's security appendix; a full reduction is future work.

\paragraph{Correctness.} Shown inline: equations~\eqref{eq:blindsign},
\eqref{eq:unblind}, \eqref{eq:lagrange} and the expansion
of~\eqref{eq:spendverify}.

\paragraph{Unforgeability.} Suppose an adversary corrupting fewer than $t$
mints outputs $k$ valid spends with distinct nullifiers whose committed amounts
exceed what it was issued. Each spend contains a $\psi$-proof, so by special
soundness we extract $(\K{m_1},\K{m_2},\K{r'_p})$ with
$\Gt{K'} = \K{m_1}\Gt{X_1} + \K{m_2}\Gt{X_2}$ and $\Go{P'} = \K{m_1}\Go{G_p} + \K{r'_p}\Go{H_p}$;
the pairing check then says $(\Go{B'},\Go{\sigma'})$ is a PS signature on
$(\K{m_1},\K{m_2},\K{m_3})$ under the aggregate key. Distinct nullifiers mean
distinct $(\K{m_1},\K{m_2})$, hence $k$ signatures on distinct messages. Each
honest issuance produced one signature, on the attributes extracted from its
$\varphi_{\Go{B}}$-proof, and those attributes had range-proven amounts; by
binding of $\Go{P}$ (DL) the amount in the signature is the amount in the range
proof. If the $k$ messages are among the issued ones, the sum of the amounts is
bounded by what was issued, contradicting the assumption; otherwise some
message was never signed by the honest mints, and because fewer than $t$ key
shares reveal nothing about the key (Shamir), the adversary has forged a PS
signature, contradicting PS unforgeability. The reduction needs each honest
signature to be on a fresh base, which~\eqref{eq:h} provides via the random
oracle $\Hg$ and the binding of $\Go{C_m}$: two requests with the same
$\Go{C_m}$ open to the same attributes, so they are the same message. This is
the step that fails for the fully amortised batch.

\paragraph{Blindness.} A mint's view of an issuance is
$(\vv{C}, \vv{R}, \vv{s})$ plus the range proof. $\Go{P}$, $\Go{C_m}$ and
$\Go{C_j}$ are perfectly hiding because $\K{r_p},\K{r_m},\K{r_j}$ are uniform;
$(\vv{R},\vv{s})$ is simulatable without the witness (Appendix~\ref{app:sigma});
and the range proof is zero knowledge. Hence the view is simulatable from the
range alone. Blindness holds information-theoretically for the commitments and
computationally for the proofs, against any number of colluding mints.

\paragraph{Unlinkability.} An adversary holding all key shares sees at
issuance $(\Go{B}, \vv{C}, \pi)$ and at spend
$(\Go{B'}, \Go{\sigma'}, \Gt{V}, \Go{P'}, \Gt{K'}, \auth, \pi')$. The spend
elements are determined by $(\Go{B},\Go{\sigma})$, the attributes and fresh
randomness $\K{r},\K{r'},\K{r'_p}$. Under DDH in $\GG{1}$, $(\Go{B},\K{r}\Go{B})$
is indistinguishable from $(\Go{B},\Go{U})$ for random $\Go{U}$, and
$\Go{\sigma'}$ is a function of $\Go{B'}$ and public data; $\Go{P'}$ is a fresh
perfectly hiding commitment; $\Gt{K'}$ is independent of the issuance
transcript because $\K{m_2}$ appeared there only inside hiding commitments;
and $\auth$ likewise appeared only as $\K{m_3}$ inside hiding commitments.
Hence the spend transcript is simulatable from the public key, the attributes'
nullifier and $\auth$, none of which the issuance transcript determines. Note
that this argument needs $\K{r'_p}$ to be fresh; the prototype's reuse of
$\K{r_p}$ breaks it outright (Section~\ref{sec:impl}).

\paragraph{Double-spend detection.} $\Gt{K'}$ is a deterministic function of
$(\K{m_1},\K{m_2})$, so two spends of one note coincide. Two different notes
have independent uniform $\K{m_2}$, so their nullifiers coincide with
probability $1/p$. A spender cannot present a different nullifier for the same
note: the pairing check fixes $\Gt{X_0} + \Gt{K'} + \K{m_3}\Gt{X_3}$ to be the
message under which $(\Go{B'},\Go{\sigma'})$ verifies, and by PS unforgeability
the only such messages are the issued ones; the $\psi$-proof then forces
$\Gt{K'}$ to be the attribute term of that message rather than an arbitrary
element.

\paragraph{Value confidentiality.} $\Go{P}$ and $\Go{P'}$ are perfectly
hiding. $\Gt{K'} = \K{m_1}\Gt{X_1} + \K{m_2}\Gt{X_2}$ hides $\K{m_1}$ under DDH in
$\GG{2}$ because $\K{m_2}\Gt{X_2}$ is a uniform mask; this is a one-time mask,
which suffices since a note is meant to be spent once. The balance
check~\eqref{eq:balance} reveals only the sum relation, and $\K{\delta}$ is
uniform.

\paragraph{What is not covered.} The role of $\Gt{V}$ (Section~\ref{sec:V});
the interaction between unlinkability and the public $\auth$, which a payee
could reuse across notes and thereby link its own notes (a usage question, not
a scheme one); and side channels in the prototype.

\section{Implementation Notes}
\label{sec:impl}

The prototype in this repository implements Sections~\ref{sec:scheme}
and~\ref{sec:batching} over BLS12-381, with the following deviations from the
description that are worth knowing about.

\begin{warnbox}[Prototype caveats]
\begin{itemize}[nosep,leftmargin=*]
\item \textbf{Spend-time commitment randomness.} The prototype reuses the
  issuance randomness $\K{r_p}$ when building $\Go{P'}$, so $\Go{P'} = \Go{P}$
  and a spend is trivially linkable to its issuance. The scheme requires a
  fresh $\K{r'_p}$ as in~\eqref{eq:spendelems}.
\item \textbf{Hash-to-group.} $\Hg$, $\Hs$ and the generators are implemented
  by seeding a ChaCha RNG with SHA-256 rather than a standard
  \texttt{hash\_to\_curve} ciphersuite. This is fine for
  unknown-discrete-logarithm generation but not interoperable.
\item \textbf{Checks not implemented.} $\K{m_3} \neq 0$, $\Go{B'} \neq 0$ and
  the nullifier set are not enforced by the prototype; the range proof is not
  integrated.
\item \textbf{Only the batched path is exercised.} Single-note issuance is the
  $n = 1$ case of Section~\ref{sec:batching}, and the tests run batches of two.
\end{itemize}
\end{warnbox}

\section{Open Problems}
\label{sec:open}

\begin{enumerate}[nosep]
  \item \textbf{Batching.} Replace the fully amortised proof with the per-note
        base variant of Section~\ref{sec:mitigation} or a compressed
        $\Sigma$-protocol, and decide whether inputs should additionally be
        range-proven at spend time as defence in depth.
  \item \textbf{Formal security proof.} Turn the sketches of
        Section~\ref{sec:analysis} into reductions, in particular a game-based
        balance definition and its reduction to PS unforgeability under
        $q$-MSDH-1 with the hashed base.
  \item \textbf{The element $\Gt{V}$.} Either justify it or remove it and the
        $\K{r'}$ terms of~\eqref{eq:rerand} (Section~\ref{sec:V}); removal saves
        $96$ bytes and one $\GG{2}$ multiplication per spend.
  \item \textbf{Transaction size.} The $100/100$ example exceeds the consensus
        limit in all variants. Options are a larger limit, fewer notes per
        transaction through change-making, or a smaller spend encoding.
  \item \textbf{Key rotation and nullifier pruning.} Fedimint rotates keys per
        epoch; the nullifier set and the aggregate key need a lifecycle.
  \item \textbf{Prototype fixes} listed in Section~\ref{sec:impl}, and a
        standard hash-to-curve ciphersuite~\cite{rfc9380}.
\end{enumerate}

\section{Conclusion}

Hiding the amount of a federated eCash note is possible with the same
machinery that makes Fedimint work today, threshold signing with Shamir shares
and Lagrange interpolation in the exponent, once the signature is one whose
signing map is linear in both key and messages. Pointcheval--Sanders
signatures issued Coconut-style provide that, Pedersen commitments and
Bulletproofs make the hidden amounts balanceable and bounded, and the
hidden-attribute term of the verification equation doubles as a nullifier. The
resulting notes are unlinkable, confidential and detectably single-spend. The
remaining cost is size: inputs carry about half a kilobyte each, and the one
optimisation that makes outputs cheap, a shared signature base, is also the
one that must not be used. The per-note base variant restores the security
argument at a size the consensus layer can likely absorb; proving the scheme
formally and shrinking the spend are the next steps.

\section{\texorpdfstring{$\Sigma$}{Sigma}-protocols for Linear Maps}
\label{app:sigma}

Both proofs of the scheme are instances of one protocol: a proof of knowledge
of a preimage under a linear map. Let $V$ and $W$ be finite-dimensional
$\F$-vector spaces, in our instantiations $V = \F^k$ and $W$ a product of
pairing groups, and let $\varphi : V \to W$ be linear. The public statement is
$Y \in \operatorname{im}\varphi$; the prover knows $\vv{x} \in V$ with
$\varphi(\vv{x}) = Y$. The full set of witnesses is the affine subspace
$\vv{x} + \ker\varphi$. The witness is the prover's private input and is never
transmitted.

\paragraph{Interactive protocol.}
\begin{align*}
  &\textbf{commit:}    && \vv{\rho} \sample V, \quad R = \varphi(\vv{\rho}), && \text{prover} \to \text{verifier: } R \\
  &\textbf{challenge:} && \K{\gamma} \sample \F,                              && \text{verifier} \to \text{prover: } \K{\gamma} \\
  &\textbf{respond:}   && \vv{s} = \vv{\rho} + \K{\gamma}\,\vv{x},            && \text{prover} \to \text{verifier: } \vv{s} \\
  &\textbf{verify:}    && \varphi(\vv{s}) \eqq R + \K{\gamma}\,Y .
\end{align*}

\paragraph{Properties.}
\begin{description}[nosep,leftmargin=1.2em]
\item[Completeness.] $\varphi(\vv{s}) = \varphi(\vv{\rho}) + \K{\gamma}\varphi(\vv{x}) = R + \K{\gamma}Y$.
\item[Special soundness.] Two accepting transcripts $(R,\K{\gamma},\vv{s})$ and
  $(R,\K{\gamma'},\vv{s}')$ with $\K{\gamma} \ne \K{\gamma'}$ give
  $\varphi(\vv{s}-\vv{s}') = (\K{\gamma}-\K{\gamma'})Y$, so
  $(\K{\gamma}-\K{\gamma'})^{-1}(\vv{s}-\vv{s}')$ is a witness. The knowledge
  error is $1/p$.
\item[Honest-verifier zero knowledge.] A simulator samples $\vv{s} \sample V$
  and $\K{\gamma} \sample \F$ and sets $R = \varphi(\vv{s}) - \K{\gamma}Y$; the
  transcript is distributed exactly as a real one. Since $\vv{s}$ is uniform on
  $V$, nothing about which element of $\vv{x} + \ker\varphi$ the prover holds
  leaks; in particular $\vv{s}$ is a one-time pad of $\K{\gamma}\vv{x}$ under
  $\vv{\rho}$.
\end{description}

\paragraph{Fiat--Shamir.} The protocol is public-coin, so the challenge can be
computed as $\K{\gamma} = \Hs(\dtag \,\|\, Y \,\|\, R)$ with $\Hs$ a random
oracle~\cite{fs86}. The proof is $(R,\vv{s})$, or in the compact form
$(\K{\gamma},\vv{s})$ with the verifier recomputing $R = \varphi(\vv{s}) - \K{\gamma}Y$
and re-deriving $\K{\gamma}$. Hashing $Y$ binds the proof to the statement; the
domain tag prevents a proof for one map from being replayed against another.
Soundness in the random-oracle model follows from special soundness by the
forking lemma, with a loss linear in the number of hash queries.
